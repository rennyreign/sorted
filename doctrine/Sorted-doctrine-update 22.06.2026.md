# Sorted. Overview

Help small businesses build more trust, generate more enquiries, and win more customers through digital modernization.

---

## What Sorted Is

Businesses arrive with a digital problem.

Sorted applies the appropriate solution.

The business improves.

### More Trust.

### More Enquiries.

# Sorted Operating Doctrine

## Purpose

Sorted exists to help small businesses build more trust, generate more enquiries, and win more customers through digital modernization.

This document defines how Sorted operates internally to achieve that outcome.

It is not a customer-facing document.

It is the operating philosophy behind the factory.

---

# Principle 1: We Don't Sell. We Show.

Traditional service businesses sell promises.

Sorted delivers evidence.

Before asking for commitment, we attempt to demonstrate value.

Examples:

- Website Mockup
- Website Score
- Review Audit
- Follow-Up Audit
- AI Receptionist Demo
- Lost Revenue Report

These are not products.

They are acquisition artifacts.

Their purpose is to create trust before a sales conversation begins.

---

# Principle 2: Every Capability Requires Two Artifacts

Every solution inside Sorted must have:

### Acquisition Artifact

How we demonstrate the problem and reveal the opportunity before engagement.

Examples:

- Website Mockup
- Review Audit
- AI Demo Agent
- Mystery Shop Report

### Delivery Artifact

The operational system that solves the problem after purchase.

Examples:

- Website Build
- Review Engine
- Follow-Up Automation
- CRM Infrastructure

If a capability cannot be demonstrated before purchase, it is incomplete.

---

# Principle 3: Trust Before Transaction

The objective of the acquisition engine is not immediate revenue.

The objective is trust.

Trust creates conversations.

Conversations create opportunities.

Opportunities create customers.

The acquisition engine exists to systematically earn attention and trust from businesses that have never heard of Sorted before.

---

# Principle 4: Progressive Revelation

Customers do not need to understand Sorted.

Customers only need to understand the next relevant problem.

We never attempt to explain the entire system.

We reveal only the next useful doorway.

Examples:

Website Problem

→ Website Solution

Review Problem

→ Review Solution

Follow-Up Problem

→ Follow-Up Solution

The architecture remains hidden.

The outcome remains visible.

---

# Principle 5: The Factory Over The Artisan

Sorted is not built around individual genius.

Sorted is built around repeatable systems.

The objective is not bespoke creativity.

The objective is reliable business improvement.

Whenever possible:

- Systems replace memory
- Operators replace complexity
- Infrastructure replaces heroics

The business must become increasingly independent of individual people over time.

---

# Principle 6: The China Principle

Complex systems become scalable when decomposed into small deterministic units.

Every workflow should be reduced into the smallest practical operational boundary.

Examples:

- Prospect Discovery Operator
- Website Analysis Operator
- Scoring Operator
- Mockup Operator
- Build Operator
- QA Operator
- Reporting Operator

Each operator performs one job.

The intelligence emerges from the system, not the individual operator.

---

# Principle 7: Operators Are The Destination

An operator is the intended operational boundary of a capability.

Operators define:

- Inputs
- Outputs
- Rules
- Success Criteria
- State Transitions

An operator may initially be executed through:

- A human process
- An AI agent skill
- A human-assisted AI workflow
- A dedicated autonomous operator

The implementation is not the operator.

The operational boundary is the operator.

As capabilities mature, execution should progressively move from humans to agents, and from agents to fully autonomous operators.

Example:

Human Process

→ Agent Skill

→ Operator

→ Operator Network

The objective is not immediate automation.

The objective is clearly defined operational boundaries that can be automated when economics, scale, and available tooling make it advantageous.

Every operator should ultimately produce a stateful completion that advances the system to the next stage.

State progression is the true measure of operational completion.

---

# Principle 8: Skills Before Operators

The fastest path to capability is not always full operatorization.

When a capable agent can execute multiple sequential procedures reliably, the preferred implementation may be a reusable skill running inside that agent.

Operators are created when:

- Concurrency becomes necessary
- Scale becomes necessary
- Reliability becomes necessary
- Cost efficiency becomes necessary

Until then, a well-defined skill executed by an agent is a valid embodiment of the operational procedure.

The purpose of skills is velocity.

The purpose of operators is scale.

# Principle 9: State-Driven Systems

Operators should communicate through state, not direct dependency.

The system maintains a single source of truth.

Work progresses through status changes.

Example:

DISCOVERED

→ ANALYZED

→ SCORED

→ MOCKUP_GENERATED

→ OUTREACH_READY

→ ENGAGED

→ CUSTOMER

Each operator responds to state changes.

This creates resilience, observability, and scalability.

---
