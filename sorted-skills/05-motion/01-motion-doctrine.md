# Motion Doctrine

## Purpose

Motion exists to reinforce understanding.

Motion should never exist purely for decoration.

Users should notice the result of motion.

Not the animation itself.

Motion communicates:

Hierarchy.

Cause and effect.

Feedback.

Confidence.

Continuity.

---

# Core Philosophy

Good motion feels inevitable.

Poor motion feels animated.

The interface should feel alive.

Not playful.

---

# Rule 01

Motion should explain.

Every animation should answer:

"What changed?"

If it does not,

remove it.

---

# Rule 02

Motion should reduce cognitive load.

Movement should guide attention.

Never compete for it.

---

# Rule 03

Fast interactions.

Slow atmosphere.

Buttons:

Fast.

Page transitions:

Medium.

Large imagery:

Slow.

---

# Rule 04

Objects have weight.

Large objects move slower.

Small objects move faster.

Motion should feel physically believable.

---

# Rule 05

Opacity before movement.

Fade.

Then translate.

Never teleport elements.

---

# Rule 06

Avoid surprise.

Motion should confirm expectation.

Not create novelty.

---

# Validation

If motion is removed,

the interface should still function perfectly.
