# Mockup Deconstruction Operator

## Context

We are building an AI-native website modernization factory (Sorted).

Current workflow:

```
Business Website
↓
Screenshot Capture
↓
GPT-Image Mockup Operator
↓
Beautiful Modernized Website Mockup (single image)
↓
Mockup Deconstruction Operator
↓
Asset Generation Operator
↓
Website Build
```

The bottleneck is the manual asset extraction + replacement process:

- a human identifies every image needed
- a human decides whether to crop, regenerate, find stock, or reuse
- a human prepares production-ready assets for the build

The GPT-image mockup is **the art-direction reference** (composition, style, subject matter, lighting, and vibe). Our job is to convert that visual into deterministic, machine-readable production inputs.

---

## Objective

Accept a completed website mockup image and produce a structured JSON representation of:

- page structure
- section hierarchy
- copy blocks
- asset requirements (with extraction guidance)
- image manifest (IDs + specs)
- build instructions / implementation notes

This JSON becomes the handoff artifact for downstream operators (especially Asset Generation).

---

## Input

Single image:

```
website-mockup.jpg
```

This image represents a fully designed website page generated by GPT-image and acts as the reference for what the final site should look like.

---

## Output

Generate a JSON document with the following top-level schema:

```json
{
  "page_type": "",
  "sections": [],
  "assets": [],
  "components": [],
  "copy": [],
  "build_notes": []
}
```

---

## Section Extraction

Identify every major section in top-to-bottom order.

Example:

```json
{
  "id": "hero",
  "type": "hero",
  "position": 1
}
```

Expected section types:

- hero
- features
- services
- process
- statistics
- testimonials
- pricing
- gallery
- CTA
- footer

If a section is unknown:

```json
{
  "type": "custom"
}
```

---

## Asset Manifest (production-oriented)

Every visual asset should be identified.

This operator should treat the mockup as the *visual reference*, so assets may be:

- **extractable** directly from the mockup (crop/segment)
- **recreatable** (generate a clean/high-res version matching the mockup)
- **stock** (find a close match)
- **reused** (existing brand assets like logos)

### Required fields

```json
{
  "id": "hero_founder",
  "type": "person",
  "description": "Professional fitness coach seated in premium gym; dark premium lighting; confident pose",
  "priority": "critical",
  "source": "generate"
}
```

Allowed `source` values:

```json
[
  "reuse",
  "generate",
  "stock"
]
```

### Recommended fields (to enable deterministic extraction + variants)

Add these when you can infer them from the mockup:

- `section` (e.g. `"hero"`)
- `slot` (e.g. `"hero.primary_image"`, `"testimonial.avatar"`)
- `bbox` bounding box in mockup coordinates (for extraction)
- `aspect_ratio` (e.g. `"16:9"`, `"1:1"`, `"4:5"`)
- `variants` (e.g. `["desktop", "mobile"]` or pixel targets)
- `mode_hint` (e.g. `"extract"` vs `"recreate"` when obvious)

Example:

```json
{
  "id": "testimonial_avatar_1",
  "type": "avatar",
  "description": "Client headshot; neutral background; premium fitness vibe",
  "priority": "medium",
  "source": "generate",
  "section": "testimonials",
  "slot": "testimonial_cards.avatar",
  "aspect_ratio": "1:1",
  "bbox": { "x": 1240, "y": 3550, "w": 180, "h": 180 }
}
```

## Copy Extraction

Extract visible copy as structured entries.

Example:

```json
{
  "section": "hero",
  "type": "headline",
  "text": "Fewer People. Faster Results."
}
```

Example:

```json
{
  "section": "hero",
  "type": "subheadline",
  "text": "Personalised coaching for those who want direct access."
}
```

---

## Component Identification

Infer reusable component patterns (design system primitives).

Example:

```json
{
  "component": "hero_v3"
}
```

Example:

```json
{
  "component": "testimonial_cards_v2"
}
```

These become future Sorted design system components.

---

## Build Notes

Generate implementation guidance inferred from the mockup.

Example:

```json
{
  "layout": "two-column hero",
  "style": "premium fitness",
  "theme": "dark",
  "accent_color": "#ff0000",
  "responsive_priority": true
}
```

## Success Criteria

Given a GPT-generated redesign image, the operator should:

- identify all major sections
- identify all required visual assets (as a production-oriented manifest)
- infer reusable components
- extract visible copy
- produce a valid JSON handoff artifact

This operator eliminates the manual “what images do I need next?” step by turning the mockup into structured, deterministic production inputs.
