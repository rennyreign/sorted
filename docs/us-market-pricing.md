# UK and US pricing

One website shares its design and routes across both markets. The public offer is £3,000 in the UK (£1,500 + £1,500), or $3,500 in the US ($1,750 + $1,750). These are fixed commercial prices, not exchange-rate conversions.

Value: Trust and Customers. This removes the gap between the currency a visitor expects, the offer they see and the payment requested. Verify by following each market from the homepage through pricing, the mockup request and workspace next steps.

## Public market selection

The header selector saves a manual choice in localStorage (`sorted-market`). An explicit `?market=US` or `?market=UK` link sets the market on arrival. A later selector choice removes that query parameter so refreshing cannot undo the choice.

Without either, the browser makes a country-only IP lookup to https://api.country.is/ (https://country.is/ documents the API), with a three-second timeout, no credentials and no referrer. The lookup necessarily exposes the visitor's IP to that service; this is disclosed in the privacy notice. US defaults to USD; all other countries and failed lookups default to GBP. Automatic results are cached for the browser session; manual choices persist. No precise location permission is requested.

Examples:

- `https://sortmydigital.site/?market=US`
- `https://sortmydigital.site/pricing/?market=US`

The static HTML initially contains UK pricing; JavaScript applies the market after hydration. Metadata mentions both fixed prices. This is currency localisation, not a separate US SEO site or a rewrite of historical results.

## Workspace offers

Workspace currency is a commercial property, not a visitor preference. Mockup requests capture `market` and `currency` in the existing `lead_answers` JSON field. New US requests therefore receive the standard USD offer whenever their workspace is opened, regardless of viewer IP or selector choice. Leads without that information retain the existing UK default. The optional `lead_answers` column already has a repository migration; older installations fall back to the existing workspace query.

Client-specific `WORKSPACE_OVERRIDES` in `lib/workspace.ts` take precedence. Existing overrides without a currency remain GBP. For a US prospect acquired outside the mockup form, add an explicit offer:

```ts
offer: {
  currency: "USD",
  total: 3500,
  deposit: 1750,
  balance: 1750,
  stripePaymentUrl: "", // Replace only with this client's USD deposit link.
  bankTransferEnabled: false,
},
```

Changing currency resets inherited pricing and payment methods before applying explicit fields. A USD workspace cannot inherit the shared GBP Stripe link or show the UK bank-transfer instructions. The shared US deposit link belongs in `WORKSPACE_US_OFFER` in `lib/workspace.ts`; a client-specific link can override it. Without a USD link, the payment dialog honestly shows that checkout is pending. New USD links must charge the agreed dollar deposit; they are not generated by this change.

Tracking examples, next steps, project balances, deposit dialogs and the legacy review-next flow all format amounts using the workspace offer. Existing signed quotes, invoices, historical case-study amounts and affiliate payouts remain in their agreed currency. New US quote/agreement pages must use the USD offer and `formatMoney()` from `lib/market-pricing.ts`; existing UK documents must not follow the public selector.

Local-only fixture: `/workspace/?slug=nexus-accounting-us&route=next-steps`. The original `nexus-accounting` fixture remains GBP.
